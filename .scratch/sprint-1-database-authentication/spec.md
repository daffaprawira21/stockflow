# Sprint 1 — Database Foundation and Authentication

## Problem Statement

Sprint 0 delivered a runnable Next.js application, but StockFlow still has no persistent data layer and no way to identify an administrator. Every later sprint (Products, Inventory, Orders, Dashboard) depends on the eight entities defined in `docs/database/database-design.md` and on server-side session authentication defined in `docs/api/api-contract.md`.

Without this foundation, product and order work would be built against an unvalidated schema, and business rules such as non-negative stock and immutable audit records would live only in application code.

## Solution

Implement the approved database design as a Prisma 7 schema on PostgreSQL, including the constraints Prisma cannot express, and deliver administrator authentication end to end: a seeded admin, password hashing, server-side sessions, `login`/`logout`/`me` API endpoints, page protection, and a login interface.

The sprint ends with a working login flow backed by real database records, a repeatable test database, and automated checks that will gate every later sprint.

## User Stories

1. As a developer, I want the approved schema versioned as Prisma migrations, so that every environment has the same database structure.
2. As a developer, I want database-level constraints for inventory integrity, so that invalid stock and audit records cannot be persisted even by a buggy service.
3. As a developer, I want a local and CI test database that can be reset repeatably, so that integration and concurrency tests are trustworthy.
4. As a developer, I want runtime-validated environment configuration, so that misconfiguration fails immediately and clearly.
5. As an administrator, I want to log in with an email and password, so that I can access protected application areas.
6. As an administrator, I want my session to expire after a fixed 12 hours, so that an unattended browser does not stay authenticated indefinitely.
7. As an administrator, I want logging out to revoke my session on the server, so that the cookie alone cannot restore access.
8. As an administrator, I want to see who I am signed in as, so that I can confirm the active account.
9. As a developer, I want unauthenticated page visits redirected to login and unauthenticated API calls rejected with a JSON error, so that protection is consistent and testable.
10. As a developer, I want the sprint verified by unit, integration, and end-to-end tests, so that later work can change internals without silently breaking authentication.

## Implementation Decisions

### Toolchain baseline

- Adopt ESM: `"type": "module"` in `package.json`; `tsconfig` `target: "ES2023"`, `module: "ESNext"`, `moduleResolution: "bundler"`. Keep `strict: true`.
- `next.config.ts` must export exactly one config object via `export default`. Remove the trailing `module.exports` block. Enable `typedRoutes: true`. Do not enable `cacheComponents`.
- Turbopack remains the default bundler; do not add a custom `webpack` configuration.

### Dependency pinning

Verified against the npm registry on 2026-11-13: the `latest` dist-tag of the `prisma` CLI points at `8.0.0-rc.33`, which no longer provides `migrate`/`generate`.

- `prisma@7.10.1` (dev), `@prisma/client@7.10.1`, `@prisma/adapter-pg@7.10.1`, `pg@^8.16.3`.
- `zod@4.6.7`, `bcryptjs@3.0.3`.
- `tsx`, `dotenv` (dev) for the seed script and Prisma config.
- All CLI invocations use `npx prisma@7.10.1`, never unpinned `npx prisma`.

### Prisma configuration

- Use `prisma7.config.ts` (the 7.10 default) with `import "dotenv/config"`, `schema`, `migrations.path`, `migrations.seed`, and `datasource.url` read from `DATABASE_URL`.
- The `datasource` block in `schema.prisma` contains only `provider = "postgresql"` (v7 removed `url` from the schema).
- Generator: `provider = "prisma-client"`, `output = "../lib/generated/prisma"`. Import `PrismaClient` from the output path, not `@prisma/client`.
- The generated client is gitignored and regenerated by `postinstall` and `prebuild`. Prisma 7 no longer generates automatically after `migrate dev`.
- Use a `globalThis` singleton with `new PrismaPg({ connectionString })`. Never call `$disconnect()` in server code.

### Schema conventions

- Models use PascalCase singular names; tables are mapped with `@@map` to the snake_case names in the design document. Fields are camelCase with `@map` to snake_case columns.
- Native types: `@db.Uuid` for identifiers, `@db.Decimal(15, 2)` for money, `@db.Timestamptz(3)` for timestamps, `@db.VarChar(n)` where the design specifies a length.
- Primary keys use `@default(uuid(7)) @db.Uuid`. Identifiers are application-generated; raw SQL inserts must supply `id`.
- Foreign keys use `onDelete: Restrict` per the design document.
- All eight entities from the design document are created in this sprint: `users`, `sessions`, `products`, `orders`, `order_items`, `stock_movements`, `order_status_history`, `idempotency_records`.
- Unique and composite-unique constraints and indexes follow `docs/database/database-design.md` §6 and §7.

### Constraints Prisma cannot express

Prisma 7 has no `CHECK` support in schema or migrate. A hand-edited migration adds every constraint listed in the design document §6.3, including:

- `products.price >= 0`, `products.stock >= 0`
- `orders.total_amount >= 0`, `orders.status IN ('PENDING','CONFIRMED','SHIPPED','CANCELLED')`
- `order_items.quantity > 0`, `unit_price >= 0`, `subtotal >= 0`
- `stock_movements.quantity_delta <> 0`, `quantity_before >= 0`, `quantity_after >= 0`
- `stock_movements.quantity_after = quantity_before + quantity_delta`
- Movement-type sign rules and the non-empty `reason` requirement for manual adjustments

Because Prisma does not introspect `CHECK` constraints, each later migration must be reviewed to confirm none were dropped.

The `order_number` sequence is intentionally **not** created in this sprint; it belongs to the Orders sprint.

### Application structure

```text
app/api/auth/login/route.ts
app/api/auth/logout/route.ts
app/api/auth/me/route.ts
app/login/page.tsx
modules/auth/{password,session,service,schemas}.ts
lib/db.ts
lib/env.ts
lib/api/{response,errors,guard,origin}.ts
prisma/schema.prisma
prisma/seed.ts
proxy.ts
```

Route handlers stay thin: validate input, call the module, map results to the response envelope.

### Authentication behavior

- Password hashing uses bcryptjs with cost 12. Verification always executes a bcrypt comparison, using a fixed dummy hash when the email is unknown, so response timing does not reveal account existence.
- Session token: 32 random bytes encoded as base64url, sent only in the cookie. Store only the SHA-256 hex digest in `sessions.token_hash`.
- Cookie: name `stockflow_session` (overridable by env), `HttpOnly`, `Secure` in production, `SameSite=Lax`, `Path=/`, `Max-Age=43200`. The session lifetime is fixed and not extended by activity.
- Session validation queries the database on every protected request and treats a session as invalid at or after `expiresAt`.
- Login runs expired-session cleanup globally (`expiresAt < now`) in the same transaction that creates the new session, and never deletes unexpired sessions.
- Logout deletes the current session record and clears the cookie.
- Login failure returns HTTP 401 `UNAUTHENTICATED` with an identical message for unknown email and wrong password.
- State-changing requests (`POST`, `PATCH`, `DELETE`) validate the `Origin` header against `ALLOWED_ORIGINS` (falling back to the request origin) and return 403 `FORBIDDEN` on mismatch.
- `proxy.ts` protects application pages only, redirecting unauthenticated visits to `/login`. It excludes `/api/*`, `/login`, and Next.js static assets. Every API handler enforces authentication itself via the shared guard, which returns JSON `401 UNAUTHENTICATED`.

### Seed

`prisma/seed.ts` upserts an administrator from `ADMIN_EMAIL` / `ADMIN_PASSWORD`, requires a password of at least 12 characters, and refuses to run when `NODE_ENV=production` unless `ALLOW_SEED=true`. Re-running the seed updates the password hash so local environments remain deterministic.

### Environment variables

`lib/env.ts` parses and validates with Zod, failing fast:

- `DATABASE_URL`
- `TEST_DATABASE_URL` (test scripts only)
- `ADMIN_EMAIL`
- `ADMIN_PASSWORD`
- `SESSION_COOKIE_NAME` (default `stockflow_session`)
- `ALLOWED_ORIGINS` (comma-separated, optional)
- `ALLOW_SEED` (optional)

`.env.example` documents all of them. `.env*` files are gitignored.

## Testing Decisions

A good test verifies observable behavior through the highest useful seam, uses isolated and repeatable setup, and fails with a clear message.

- Unit tests (Vitest): password hash/verify including the dummy-hash path, session token hashing, Zod request schemas, origin validation, response envelope and error mapping.
- Integration tests (Vitest + PostgreSQL): run against `stockflow_test`. Cover login success and failure, cookie issuance, expired-session rejection, logout revocation, expired-session cleanup that preserves unexpired sessions, `me` for authenticated and unauthenticated callers, and database constraint rejection for negative stock, wrong movement sign, and `quantity_after <> quantity_before + quantity_delta`.
- Test harness: global setup applies migrations with `migrate deploy`; tests truncate tables between cases; concurrency-sensitive tests create their own clients and transactions.
- `prisma migrate reset` is only invoked by a dedicated test script that sets `PRISMA_USER_CONSENT_FOR_DANGEROUS_AI_ACTION` for the test database. It is never used against development or production databases.
- End-to-end tests (Playwright): unauthenticated visit redirects to `/login`; successful login reaches the authenticated page; logout returns to `/login` and the session no longer works.
- Business-logic unit coverage for `modules/auth` must be at least 80%, per `docs/testing/testing-strategy.md` §9.1.
- Sprint 0's database-free smoke test remains valid; new E2E tests use the dedicated PostgreSQL test database.

## Out of Scope

- Product, inventory, order, dashboard, and audit features.
- Order-number sequence creation and idempotency handling.
- Server Actions; the login form calls the REST endpoint.
- CSRF tokens and login rate limiting (explicitly excluded from the MVP by the API contract).
- Multiple roles or permissions beyond `ADMIN`.
- Deployment, hosting configuration, or production secret management.
- `cacheComponents` / PPR adoption.
- Advancing into Sprint 2.

## Definition of Done

All of the following must be true before the sprint is considered complete:

- `npm run typecheck`, `npm run lint`, `npm test`, `npm run test:integration`, and `npm run test:e2e` pass.
- `npx prisma@7.10.1 validate` and `npx prisma@7.10.1 migrate deploy` succeed against `stockflow_test`.
- The schema contains all eight entities with the native types and constraints from the design document.
- Database constraint tests fail as expected when invalid stock or audit records are inserted.
- Login, logout, and `me` match the response envelope and error codes in `docs/api/api-contract.md`.
- An unauthenticated page visit redirects to `/login`; an unauthenticated API call returns `401 UNAUTHENTICATED`.
- Logout deletes the session record and clears the cookie.
- Coverage for `modules/auth` is at least 80%.
- `README.md` documents setup, environment variables, database commands, and test commands.
- CI runs typecheck, lint, unit, and integration tests with a PostgreSQL service container.
