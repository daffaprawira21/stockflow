# Task workflow

## Scope and approval

Work only on the task explicitly requested. Do not add unapproved features, business rules, dependencies, or architectural changes, or advance to another roadmap phase without a request. Create additional project documents only when requested or approved.

Read-only inspection and audits may proceed when requested. Before non-trivial file changes, explain the proposed changes and wait for developer approval.

## Work and report

Inspect relevant files and check `git status` before modifying files. Keep changes focused, preserve existing developer changes, and verify outcomes before reporting success.

At task completion, report what changed, what was verified, what remains unverified, and any unresolved issue or decision needing approval. Stop when the requested task is complete.
